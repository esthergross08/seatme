# SeatMe UX Review — 2026-08-29

A design/UX pass through the whole product, requested to catch snags before the next push. Companion to `AUDIT_2026-08-18.md`; where that one's findings are still open, they're noted briefly rather than repeated in full.

**Status: everything below is now fixed (2026-08-29, same day)**, with one deliberate change of approach — "no confirmation or undo on destructive actions" was addressed with undo, not a confirmation dialog, per direction. See `ROADMAP.md`'s "UX review pass" entry for what actually shipped for each item. Left as-is here for the record.

## New findings

**The table setup row overflows on mobile.** In the Tables tab, each table type is one `flex` row holding the name field, a "Tables" count box, a "Seats each" count box, a shape dropdown, and a delete button, with no wrapping. On a phone-width screen that's more content than fits — the row will run off the right edge or squeeze every field down to nearly unusable width. This is the same class of bug as the table-setup screen never having gotten a mobile pass, and it's the first thing anyone using SeatMe on a phone hits, since Tables is step one. Worth wrapping this row (stack the fields, or drop to two rows) below the `sm:` breakpoint.

**Dragging a table on the floor plan doesn't work on a touchscreen.** Repositioning a table (Seating → Map view) is wired entirely through mouse events (`onMouseDown` + `window` `mousemove`/`mouseup` listeners), which touch browsers don't fire. Seating a *guest* has a tap-to-pick-then-tap-to-place fallback for exactly this reason, but moving a *table* has no equivalent — so on mobile, the floor plan layout is view-only. Not urgent if most editing happens on a laptop, but worth knowing it's not just "a bit fiddly" on a phone, it's non-functional.

**Renaming a table on the map makes the AI assistant blind to that name.** The per-table custom name (typed directly into a table on the floor plan) lives in `tableNameOverrides`, which is applied on the client via `buildTables(tableGroups, tableNameOverrides)`. The assistant's context-builder and its own `seat_guest` apply-logic both call `buildTables(tableGroups)` — without the overrides — so the moment you rename a table (e.g. "Table 3" → "Sweetheart Table"), the assistant stops knowing it exists. Asking it to "seat Alex at the Sweetheart Table" will fail with a not-found error, even though the chat's own placeholder text ("e.g. move Sara to Family Round 1") implies exactly this should work. This is a small, contained fix — thread `tableNameOverrides` into the same two `buildTables()` calls in `app/api/agent/route.ts` and `applyAgentOperations`'s `seat_guest` case.

**The floating chat bubble likely overlaps the new "Next" button on mobile.** Both are anchored to the bottom-right corner: the Assistant button sits at `bottom-20 right-6`, and the Next/Prev pane bar I added this week sits at the very bottom of each tab's content, also right-aligned. Scrolled to the end of a pane on a phone, the two are close enough that they may visually collide. Cheap to fix (extra bottom margin on the nav bar, or nudging the FAB) — flagging it here since it's a snag I introduced, not something pre-existing.

**Table-type field labels don't explain themselves out of context.** "Tables" and "Seats each" as labels next to two side-by-side number boxes read fine once you know the layout, but a first-time user scanning quickly could misread which number is the count of tables vs. seats per table — there's no visual grouping (like a mini table icon) tying the numbers to their meaning beyond the text label.

**Guest rows are dense.** Name, seated/unseated status, remove button, group chips, a note field, an RSVP badge, and a meal-choice field are all stacked in each guest row now. It reads fine at a glance but there's no visual hierarchy — dietary note and RSVP/meal sit at the same visual weight as the guest's name. For a 100+ guest wedding this list will get long and a little visually noisy; worth considering a collapsed/expanded row state (name + status by default, click to reveal note/RSVP/meal) once lists get bigger.

**Stale data left behind when a table type is deleted.** `removeTableGroup` cleans up nothing beyond the table type itself — seat assignments *do* get reconciled automatically by a reactive effect, but `tableNameOverrides` and `tablePositions` entries for that table's now-nonexistent IDs are never pruned. Harmless today (they just sit unused in the event's saved JSON), but worth a one-line cleanup in `removeTableGroup` so the data doesn't quietly accumulate.

## Still open from the 2026-08-18 audit

Re-checked against the current code — these haven't been addressed yet:

- **No confirmation or undo on destructive actions.** Removing a guest, table type, group, or constraint is still instant, no "are you sure," no undo. Confirmed by grepping the whole codebase for `confirm(` — there isn't one anywhere.
- **No way to delete an event.** Still no `deleteEvent` path in `app/events/page.tsx` or anywhere else — events accumulate on the dashboard forever.
- **Inviting a collaborator is still silent.** `InviteForm` writes the `event_members` row and shows you a small "they'll get access next time they sign in" note, but no email or notification actually goes to the invited person.
- **No search/sort on the events dashboard or guest list.** Still fine at current scale, will get noisy as either list grows.
- **Accessibility hasn't had a pass.** Color contrast, keyboard nav through the seating map, and screen-reader labels on icon-only buttons are all still unchecked.

The read-only/viewer RLS gap and the fake-sample-data-on-new-events issue from that audit are both confirmed fixed now — no changes needed there.

## Minor polish notes

**`InviteForm` and `AccountMenu`'s dropdown are still hand-styled with inline pixel CSS** rather than the Tailwind + `C` palette pattern the rest of the app moved to during the redesign. Low visual weight (small embedded widgets, not full pages) so it reads fine, but worth folding into the same pass if either gets touched again.

**The seating-tab toolbar has grown to six controls** (Map/Table toggle, Auto-generate, Clear tables, Notes, Excel, PDF) in one wrapping row. It still works — `flex-wrap` handles it — but it's getting crowded, especially once it wraps to two or three rows on a narrower screen. Not broken, just worth watching as more actions get added; a "More" overflow menu might be worth it eventually.

**Login card touches the screen edges on very narrow phones.** The sign-in card (`app/login/page.tsx`) has no horizontal margin on its outer wrapper — on a ~320-360px-wide phone the white card runs flush to both edges instead of floating with a visible gap. Cosmetic only.

## Suggested priority order

If picking a few to fix now: the table-setup mobile overflow and the assistant/table-rename blind spot are the two with real functional impact (one breaks a core screen on mobile, the other breaks a real assistant capability silently). The chat-bubble/Next-button overlap is worth a quick look since it's new. Everything else here is fine to batch into a later pass.
